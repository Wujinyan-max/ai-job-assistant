# 产品优化需求文档（PRD）

> 版本：v1.0  
> 日期：2026-09-16  
> 状态：待评审  
> 目标读者：产品、设计、前端、后端、测试

---

## 一、背景与目标

AI 求职管理平台已完成「公司 → 职位 → 简历 → 投递 → 面试 → Offer」的核心闭环，并接入大模型提供 JD 解析、简历匹配、面试题生成等能力。当前功能完整，但在用户动线、数据联动和 AI 价值外化上仍有明显断点，导致用户需要频繁手动跳转、状态维护成本高、AI 能力发现率低。

本 PRD 旨在解决以下三类问题：

1. **流程断点**：关键操作分散在不同页面，缺乏快捷入口和自动流转。
2. **数据孤岛**：简历版本、投递效果、面试复盘等数据未形成可行动的洞察。
3. **AI 隐身**：AI 功能集中在独立页面，未嵌入业务场景，用户感知弱。

**成功指标（上线后 4 周）**：

- 职位详情页「一键投递」点击率 ≥ 30%
- 面试结果更新后自动流转状态的比例 ≥ 80%
- 简历版本与投递效果关联报表的日均访问 ≥ 20 次
- 从业务页面（非 `/ai`）进入 AI 功能的流量占比 ≥ 40%

## 二、用户场景与痛点

### 场景 1：看到心仪职位想投递

**现状**：用户需记住职位名 → 切换到「投递记录」→ 点击新增 → 从下拉框重新选择职位和简历 → 填写时间 → 保存。共 5 步，且易选错职位。

**期望**：职位列表/详情直接提供「投递」按钮，自动带出职位和默认简历，2 步完成。

### 场景 2：面试结束后更新状态

**现状**：用户标记面试「未通过」后投递自动变为「已拒绝」，但标记「通过」后不会自动推进到「Offer」或提示安排下一轮。用户常忘记更新，导致看板数据失真。

**期望**：面试「通过」时主动询问下一步：「进入下一轮面试」「已拿到 Offer」「保持现状」，并自动更新投递状态。

### 场景 3：评估哪份简历更有效

**现状**：投递记录关联了简历版本，但系统没有统计「Java 后端版简历」vs「全栈版简历」的面试率差异。用户无法优化简历策略。

**期望**：提供按简历版本分组的转化率报表，帮助用户识别高绩效简历。

### 场景 4：准备面试

**现状**：AI 面试题生成入口藏在 `/ai` 页面第 4 个 Tab，用户很少主动使用。面试复盘写在文本框里，与题库完全隔离。

**期望**：收藏职位或记录面试后，自动推荐「生成面试题」；复盘内容可一键转为题库条目。

## 三、需求详情

### P0-1：职位列表「一键投递」

**描述**：在职位管理列表的每行操作区增加「投递」按钮，点击后弹出简化投递表单（自动填充当前职位 + 默认简历，可改），确认后创建投递记录并跳转看板。

**验收标准**：
- [ ] 职位列表每行显示「投递」按钮，无默认简历时提示先创建简历
- [ ] 投递表单默认填充 `jobId`、`resumeId`、`applyTime=now()`、`status=APPLIED`
- [ ] 投递成功后跳转至 `/board` 并高亮新卡片
- [ ] 无职位数据时按钮置灰

### P0-2：面试结果自动流转

**描述**：标记面试结果为「通过」时，弹窗询问用户下一步意向；选择「已拿 Offer」则投递状态改为 `OFFER`，选择「进入下一轮」则保持 `INTERVIEW` 并清空本轮结果字段供下轮使用。

**验收标准**：
- [ ] 仅当面试结果从非 PASS 改为 PASS 时触发弹窗
- [ ] 选择「已拿 Offer」后投递状态变为 `OFFER`，看板卡片移动到对应列
- [ ] 选择「进入下一轮」后自动创建新面试记录草稿（轮次+1）
- [ ] 取消操作不改变任何状态

### P0-3：Dashboard 面试提醒红点

**描述**：Dashboard 顶部统计卡区域增加「7 天内面试」红点提醒，点击直接跳转面试列表；同时浏览器标签页标题显示未读面试数。

**验收标准**：
- [ ] 有未来 7 天面试时显示红点及数量
- [ ] 点击红点跳转 `/interviews` 并筛选未来 7 天
- [ ] 无面试时红点消失
- [ ] 浏览器标题格式：`(3) 职得 JobPath`

### P1-1：简历版本效果分析报表

**描述**：Dashboard 新增「简历效果分析」卡片，按简历版本统计投递数、面试率、Offer 率，支持按时间范围筛选。

**验收标准**：
- [ ] 报表展示每份简历的：投递数、面试数、Offer 数、面试率、Offer 率
- [ ] 支持 7/30/90 天时间筛选
- [ ] 数据与投递记录实时同步
- [ ] 空数据显示引导文案「先投递几份简历再来看看」

### P1-2：看板卡片信息增强

**描述**：看板卡片增加「距今天数」「下次面试时间」「AI 匹配分」三个字段，帮助用户快速判断优先级。

**验收标准**：
- [ ] 卡片显示 `applyTime` 距今天数（如「3 天前」）
- [ ] 有未来面试时显示最早面试时间（如「明天 14:00 面试」）
- [ ] 有 AI 匹配记录时显示最近匹配分（如「匹配 85 分」）
- [ ] 无数据时对应字段隐藏，不显示「—」

### P1-3：面试复盘一键入题库

**描述**：面试编辑弹窗的「复盘总结」字段下方增加「提取到题库」按钮，调用 AI 将复盘文本拆分为面试题并加入题库。

**验收标准**：
- [ ] 复盘文本 ≥ 20 字时按钮可用，否则置灰提示
- [ ] 生成题目自动关联当前职位分类
- [ ] 生成后显示成功数量，并跳转题库查看

### P2-1：默认简历强制选择

**描述**：新增投递时若用户未设默认简历，表单顶部显示警告条，必须手动选择简历后才能提交。

**验收标准**：
- [ ] 无默认简历时显示警告：「未设置默认简历，请手动选择」
- [ ] 未选择简历时提交按钮禁用
- [ ] 设置默认简历后警告自动消失

### P2-2：薪资输入支持「N 薪」

**描述**：职位表单的薪资字段增加「薪资描述」自由文本（如「15-30K·14薪」），与数字范围并存，列表优先显示描述。

**验收标准**：
- [ ] 表单新增 `salaryDesc` 字段，非必填
- [ ] 列表展示优先显示 `salaryDesc`，其次显示数字范围
- [ ] 数据库兼容旧数据

### P2-3：状态文案优化

**描述**：将投递状态「已关闭」改为「已放弃」，避免歧义；职位状态「已关闭」保持不变。

**验收标准**：
- [ ] 数据库枚举值不变，仅前端展示文案修改
- [ ] 看板、列表、筛选器、统计图表同步更新

## 四、非功能需求

- **性能**：报表接口响应时间 ≤ 500ms（P95）
- **兼容性**：支持 Chrome / Edge / Safari 最近两个版本
- **数据安全**：简历效果分析仅统计当前登录用户数据，接口需校验 `user_id`
